    Admin Control Plane¶

    The Admin Control group is where operators manage the system's configuration and inspect its audit trail: competitors and their sources, per-source schedules, the scan console, run history, news profiles (with full versioning), and the audit log. These screens perform soft-deleting CRUD over the control-plane tables and record every mutation to AdminAuditLog (with before/after/diff and originating IP).

    Admin Competitors & Sources¶

    Screens: admin-competitors (loader loadAdminCompetitors), admin-sources (loader loadAdminSources)

    CRUD over competitors and their sources. Competitors: POST /admin/competitors (201), GET /admin/competitors?active_only, GET /admin/competitors/{id}, PATCH /admin/competitors/{id}, DELETE /admin/competitors/{id} (204). Sources can be created nested under a competitor (POST /admin/competitors/{id}/sources) or flat (POST /admin/sources, which requires a competitor_id), and listed via GET /admin/sources?competitor_id.

    Deletes are soft

    DELETE on a competitor or source deactivates the row (deactivate_competitor) rather than removing it. Filter with active_only / is_active to hide deactivated rows.

    See Add a Competitor & Sources.

    Schedules¶

    Screen: admin-schedules · loader loadAdminSchedules

    Manages one SourceSchedule per source. Endpoints: GET /admin/sources/{id}/schedule (404 if none), POST /admin/sources/{id}/schedule (201; 409 if a schedule already exists; computes next_run_at and audits), PATCH /admin/sources/{id}/schedule (recomputes and audits), DELETE /admin/sources/{id}/schedule (204), and GET /admin/schedules?enabled_only.

    A schedule's schedule_type is one of manual | hourly | daily | weekly | cron. Cron schedules use a cron_expression evaluated with croniter; the next run is computed by _compute_next_run.

    30-minute minimum frequency

    Guardrails cap how aggressively a source can be scanned: MIN_FREQUENCY_MINUTES = 30, MAX_QUERY_BUDGET = 20, MAX_PAGES = 50, MAX_CONCURRENT_SCANS = 10. A schedule cannot run more often than every 30 minutes.

    Scan Console¶

    Screen: admin-scan-console · loader loadAdminScanConsole

    The manual scan trigger — six request types, background submission (202), and run polling. This screen has its own deep-dive: see the Manual Run Console.

    Runs¶

    Screen: admin-runs · loader loadAdminRuns

    The run list with a jobs drill-down. It lists runs (GET /admin/runs?limit&status), shows a single run (GET /admin/runs/{id}), and drills into per-source job detail (GET /admin/runs/{id}/jobs — SourceScanLog rows with resolved source/competitor names, status, attempt count, error_type/error_message, and candidate_signals_count). Use it to review what a run did and where it failed.

    News Profiles¶

    Screen: admin-news-profiles · loader loadAdminNewsProfiles

    The news-profile editor with full versioning, rollback, and two dry-run tools. Core endpoints: GET /admin/news-profiles, GET /admin/competitors/{id}/news-profile (404), POST (201; 409 if one exists; records v1 + audit), PATCH (updates, snapshots a version, audits the diff), and DELETE (204 + audit).

    • Versioning & rollback — GET .../news-profile/versions?limit=20 lists snapshots; POST .../news-profile/rollback/{version_id} applies a snapshot and records a new version with is_rollback = true plus an audit entry.
    • Preview queries — GET .../news-profile/preview-queries?budget=10 returns the queries the profile would generate (build_queries_from_profile, falling back to build_queries) without running a scan.
    • Test relevance — POST .../news-profile/test-relevance { title, snippet, url } returns { decision: pass | suppress | llm_review, reasons }, running the active profile's profile_relevance_check (or fast_relevance_check if no profile is active).

    See Configure a News Profile.

    Audit Log¶

    Screen: admin-audit-log · loader loadAdminAuditLog

    The full mutation history from AdminAuditLog, via GET /admin/audit-logs?object_type&object_id&limit=100. Every control-plane change — competitor, source, schedule, or news-profile edit — writes a before/after/diff record with the originating IP. Use it to answer "who changed what, and when."
