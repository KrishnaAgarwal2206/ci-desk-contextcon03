    API — Observability¶

    This page documents the observability router (app/admin/observability_routes.py), all served under the /admin/observability/* prefix and backed by app/observability/health_aggregator.py. These endpoints power the panel's observability screens: system and source health, pipeline runs, LLM metrics and cost, incidents, maintenance actions, the ops copilot, the pipeline board, live run state, timelines, cost breakdowns, and agent load. Almost every response here is a hand-built dict (there are no response_model schemas), so the field tables below enumerate the exact keys each function returns. Costs are reported in both USD and INR (USD_TO_INR = 85). All paths below are relative to /admin/observability.

    Pipeline-board key format is load-bearing

    In GET /pipeline-board, per-competitor stage_statuses are keyed workflow:stage (for example layer2:classification), and per-stage stats are keyed workflow:stage:agent_name. The panel JavaScript depends on this exact format. Do not change the workflow:stage key format — the stage comes from AgentRunTelemetry.stage, not agent_name.

    System & Source Health¶

    GET /admin/observability/system-health¶

    Overall system health snapshot: per-component status, active issues, SLO indicators, and the last scan run. Component: Observability. Backing code: app/admin/observability_routes.py → get_system_health() → app/observability/health_aggregator.py → compute_system_health().

    Response — 200 OK → hand-built dict

    Field Type Description
    status enum healthy\|degraded\|critical Overall rollup. critical if any component is critical or a sev0 incident is open; degraded if any component is degraded or any incident is open.
    issues list[string] Human-readable problem statements accumulated across components.
    components list[object] One entry per subsystem (see below). Always five: Layer 1 Scanner, Layer 2 Intelligence, LLM Provider, Delivery, Feedback Governance.
    open_incidents int Count of incidents in status open or investigating.
    slo object SLO indicators (see below).
    last_scan_run object {id, status, started_at, sources_enqueued, sources_failed} for the most recent ScanRun (nulls/zeros if none).
    generated_at datetime (ISO 8601) When the snapshot was computed (UTC).

    Each components[] entry always has name, status (healthy\|degraded\|critical\|idle), and detail (string), plus component-specific keys:

    Component name Extra keys
    Layer 1 Scanner last_success_at (datetime|null)
    Layer 2 Intelligence signals_24h (int), changes_24h (int)
    LLM Provider calls_1h (int), error_rate_pct (float), tokens_1h (int), cost_1h_usd (float)
    Delivery sent_6h (int), failed_6h (int)
    Feedback Governance pending_proposals (int), false_positive_rate_pct (float)

    slo object:

    Field Type Description
    scan_success_rate_pct float|null Completed fraction of the last 10 scan runs.
    avg_scan_duration_seconds float|null Mean duration of completed runs in the last 10.
    llm_cost_today_usd float Estimated LLM cost since midnight UTC.
    false_positive_rate_pct float Analyst false-positive rate over 24h.
    pending_governance_proposals int FeedbackChangeProposal rows awaiting human review. 
    // Example 200 response
{
  "status": "degraded",
  "issues": ["23.5% source failure rate in last run."],
  "components": [
    { "name": "Layer 1 Scanner", "status": "degraded", "detail": "Last run: a1b2c3d4 | Failure rate: 23.5%", "last_success_at": "2026-07-09T04:00:11Z" },
    { "name": "Layer 2 Intelligence", "status": "healthy", "detail": "Signals (24h): 142 | Changes (24h): 18", "signals_24h": 142, "changes_24h": 18 },
    { "name": "LLM Provider", "status": "healthy", "detail": "Calls (1h): 60 | Error rate: 0.0% | Tokens: 84,200 | Cost: $0.612", "calls_1h": 60, "error_rate_pct": 0.0, "tokens_1h": 84200, "cost_1h_usd": 0.612 },
    { "name": "Delivery", "status": "healthy", "detail": "Sent (6h): 4 | Failed: 0", "sent_6h": 4, "failed_6h": 0 },
    { "name": "Feedback Governance", "status": "healthy", "detail": "Pending proposals: 2 | FP rate (24h): 12.0%", "pending_proposals": 2, "false_positive_rate_pct": 12.0 }
  ],
  "open_incidents": 1,
  "slo": { "scan_success_rate_pct": 90.0, "avg_scan_duration_seconds": 412.3, "llm_cost_today_usd": 3.87, "false_positive_rate_pct": 12.0, "pending_governance_proposals": 2 },
  "last_scan_run": { "id": "a1b2c3d4-…", "status": "completed", "started_at": "2026-07-09T04:00:11Z", "sources_enqueued": 34, "sources_failed": 8 },
  "generated_at": "2026-07-09T06:15:00Z"
}

    Status codes: 200 OK.

    GET /admin/observability/source-health¶

    Per-source health scorecard (failure streaks, latency, candidate rate, recommended action). Component: Observability. Backing code: app/admin/observability_routes.py → get_source_health() → app/observability/health_aggregator.py → compute_source_health(). Filtering by status and competitor is applied in the route after the aggregator runs.

    Query parameters

    Name Type Required Default Description
    status string no — Exact-match filter on the computed status field (healthy\|warning\|degraded\|critical\|never_run).
    competitor string no — Case-insensitive substring match on the competitor name.

    Response — 200 OK → list[object], sorted by descending failure streak then competitor name

    Field Type Description
    source_id string (UUID) Source identifier.
    competitor string Competitor name ("?" if unresolved).
    source_type string e.g. website, news, careers, blog, social.
    url string Source URL.
    status enum healthy\|warning\|degraded\|critical\|never_run warning at streak ≥1, degraded ≥3, critical ≥5.
    last_success_at datetime|null Most recent completed scan (from started_at).
    last_failure_at datetime|null Most recent failed scan (from started_at).
    failure_streak int Consecutive failures from newest log.
    runs_sampled int Number of logs examined (≤10). Present only when the source has run (omitted on never_run).
    avg_latency_ms int|null Mean scan latency over sampled logs.
    candidate_rate float Mean candidate signals per run.
    error_type string|null Error type of the most recent log.
    last_error string|null Most recent error message, truncated to 200 chars. Present only when the source has run (omitted on never_run).
    recommended_action string Heuristic remediation hint.

    never_run sources have a reduced shape

    Sources with no scan logs return status: "never_run", failure_streak: 0, candidate_rate: 0.0, and omit runs_sampled and last_error.

    // Example 200 response
[
  {
    "source_id": "77f0…",
    "competitor": "Dabur",
    "source_type": "careers",
    "url": "https://careers.dabur.com",
    "status": "degraded",
    "last_success_at": "2026-07-07T04:02:00Z",
    "last_failure_at": "2026-07-09T04:01:40Z",
    "failure_streak": 3,
    "runs_sampled": 10,
    "avg_latency_ms": 5400,
    "candidate_rate": 1.2,
    "error_type": "parse_error",
    "last_error": "Careers ATS returned unexpected markup near <div class=\"jobs\">…",
    "recommended_action": "Careers parser failing — ATS schema may have changed. Consider Playwright fallback."
  }
]

    Status codes: 200 OK.

    Pipeline Runs¶

    GET /admin/observability/pipeline-runs¶

    List recent Layer-1 scan runs with source-status breakdowns. Component: Observability. Backing code: app/admin/observability_routes.py → get_pipeline_runs() → app/observability/health_aggregator.py → compute_pipeline_runs().

    Query parameters

    Name Type Required Default Description
    limit int no 20 Max number of ScanRun rows (newest first).

    Response — 200 OK → list[object]

    Field Type Description
    id string (UUID) Scan run id.
    status string e.g. completed, running, failed.
    triggered_by string Who/what started the run.
    started_at datetime|null Start (UTC ISO).
    completed_at datetime|null Completion (UTC ISO).
    duration_seconds float|null End − start, 1 dp.
    sources_enqueued int Total sources enqueued.
    sources_completed int Total completed.
    sources_failed int Total failed.
    candidate_signals int CandidateSignal rows for this run.
    detected_changes int Always 0 — DetectedChange carries no scan_run_id, so it is not counted per run.
    stage_counts object {status: count} map from SourceScanLog, e.g. {"completed": 26, "failed": 8}. 
    // Example 200 response
[
  {
    "id": "a1b2c3d4-…",
    "status": "completed",

    "sources_failed": 8,
    "candidate_signals": 61,
    "detected_changes": 0,
    "stage_counts": { "completed": 26, "failed": 8 }
  }
]

    Status codes: 200 OK.

    LLM Metrics & Runs¶

    GET /admin/observability/llm-metrics¶

    Aggregate LLM usage over a time window, grouped by agent (prompt name), from LLMTrace. Component: Observability. Backing code: app/admin/observability_routes.py → get_llm_metrics() → app/observability/health_aggregator.py → compute_llm_metrics(). Costs are estimated from token usage ($0.005/1K input, $0.015/1K output); this endpoint reports USD only.

    Query parameters

    Name Type Required Default Description
    hours int no 24 Look-back window in hours.

    Response — 200 OK → hand-built dict

    Field Type Description
    window_hours int Echoes hours.
    total_calls int Trace count in window.
    total_errors int Traces with an error message.
    overall_error_rate_pct float Errors ÷ calls × 100.
    total_tokens int Input + output tokens across agents.
    total_cost_usd float Estimated total, 4 dp.
    by_agent list[object] Per-agent rows, sorted by descending cost.

    Each by_agent[] entry:

    Field Type Description
    agent string Prompt name ("unknown" if unset).
    calls int Trace count.
    errors int Error count.
    error_rate_pct float Per-agent error rate.
    avg_latency_ms int|null Mean latency.
    p95_latency_ms int|null p95 (max if <20 samples).
    input_tokens / output_tokens int Token totals.
    cost_usd float Estimated cost, 4 dp. 
    // Example 200 response
{
  "window_hours": 24,
  "total_calls": 420,
  "total_errors": 3,
  "overall_error_rate_pct": 0.7,
  "total_tokens": 1284000,
  "total_cost_usd": 8.9412,
  "by_agent": [
    { "agent": "classification", "calls": 180, "errors": 1, "error_rate_pct": 0.6,
      "avg_latency_ms": 1420, "p95_latency_ms": 2600, "input_tokens": 610000,
      "output_tokens": 92000, "cost_usd": 4.4300 }
  ]
}

    Status codes: 200 OK.

    GET /admin/observability/llm-runs¶

    Per-pipeline-run LLM cost summary. Uses LLMCostLedger (linked by pipeline_run_id) as the primary source, falling back to LLMTrace matched by the run's time window; the response indicates data_source as ledger or trace. Component: Observability. Backing code: app/admin/observability_routes.py → get_llm_runs() (hand-built in the route). Costs shown in USD and INR.

    Query parameters

    Name Type Required Default Description
    hours int no 720 Look-back window (default 30 days). Caps at 50 pipeline runs, newest first.

    Response — 200 OK → hand-built dict

    Field Type Description
    hours int Echoes hours.
    runs list[object] Per-run rows (see below).
    total_runs int Length of runs.

    Each runs[] entry:

    Field Type Description
    pipeline_run_id string (UUID) Run id.
    run_type string e.g. full, layer2.
    status string Run status.
    started_at datetime|null Start.
    duration_s float|null Duration in seconds, 1 dp.
    total_llm_calls int Prefers PipelineRun rollup, else computed.
    total_input_tokens / total_output_tokens int Token totals (rollup-preferred).
    total_cost_usd float Cost, 6 dp (rollup-preferred).
    total_cost_inr float total_cost_usd × 85, 2 dp.
    competitor_count int Competitors in run.
    error_count int Errors in run.
    data_source enum ledger\|trace Which source produced the per-agent breakdown.
    agents list[object] Per-agent breakdown (see below).

    Each agents[] entry:

    Field Type Description
    agent_name string Agent / prompt name.
    calls int Call count.
    input_tokens / output_tokens int Token totals.
    cost_usd float Cost, 6 dp.
    cost_inr float cost_usd × 85, 2 dp.
    avg_latency_ms / max_latency_ms int Latency stats.
    source enum ledger\|trace Origin of this agent row. 
    // Example 200 response
{
  "hours": 720,
  "total_runs": 1,
  "runs": [
    {
      "pipeline_run_id": "5c8e…", "run_type": "full", "status": "completed",
      "started_at": "2026-07-09T04:00:11Z", "duration_s": 412.3,
      "total_llm_calls": 320, "total_input_tokens": 610000, "total_output_tokens": 92000,
      "total_cost_usd": 4.431200, "total_cost_inr": 376.65, "competitor_count": 6,
      "error_count": 1, "data_source": "ledger",
      "agents": [
        { "agent_name": "classification", "calls": 180, "input_tokens": 410000,
          "output_tokens": 60000, "cost_usd": 2.950000, "cost_inr": 250.75,
          "avg_latency_ms": 1420, "max_latency_ms": 2600, "source": "ledger" }
      ]
    }
  ]
}

    Status codes: 200 OK.

    Incidents¶

    Incident CRUD (Incident). Bodies are untyped dict, so missing required fields return 400, not 422. Resolving an incident auto-sets resolved_at.

    The incident response shape (_serialize_incident) is:

    Field Type Description
    id string (UUID) Incident id.
    severity enum sev0\|sev1\|sev2\|sev3 Severity.
    title string Short title.
    description string|null Details.
    status string open, investigating, resolved, closed, …
    component string|null Affected component.
    affected_competitors list From affected_competitors_json (default []).
    root_cause string|null Root cause.
    blast_radius string|null Impact scope.
    suggested_actions list From suggested_actions_json (default []).
    copilot_diagnosis object|null Stored copilot diagnosis JSON.
    scan_run_id string (UUID)|null Linked scan run.
    created_by string Creator.
    created_at datetime|null Creation time.
    resolved_at datetime|null Resolution time.

    affected_sources is write-only

    affected_sources is accepted and stored on POST, but _serialize_incident does not return it. It is absent from every incident response.

    GET /admin/observability/incidents¶

    List incidents, newest first. Component: Observability. Backing code: app/admin/observability_routes.py → get_incidents() → app/observability/health_aggregator.py → list_incidents().

    Query parameters

    Name Type Required Default Description
    status string no — Exact-match filter on status.
    limit int no 50 Max rows.

    Response — 200 OK → list[object] (each is the incident shape above).

    // Example 200 response
[
  {
    "id": "0f2b…", "severity": "sev1", "title": "Dabur careers source failing",
    "description": "Parser errors on last 3 runs", "status": "investigating",
    "component": "Layer 1 Scanner", "affected_competitors": ["Dabur"], "root_cause": null,
    "blast_radius": "Dabur careers signals only", "suggested_actions": [],
    "copilot_diagnosis": null, "scan_run_id": "a1b2c3d4-…", "created_by": "admin",
    "created_at": "2026-07-09T05:00:00Z", "resolved_at": null
  }
]

    Status codes: 200 OK.

    POST /admin/observability/incidents¶

    Create an incident (status forced to open). Component: Observability. Backing code: app/admin/observability_routes.py → create_incident().

    Request body — untyped dict; keys the route reads:

    Field Type Required Default Description
    title string yes — Trimmed; 400 if empty/missing.
    severity string no "sev2" Severity level.
    description string no null Details.
    component string no null Affected component.
    affected_competitors list no [] Stored as JSON.
    affected_sources list no [] Stored as JSON (write-only — not returned).
    scan_run_id string (UUID) no null Linked scan run.
    created_by string no "admin" Creator. 
    // Example request body
{
  "title": "Dabur careers source failing",
  "severity": "sev1",
  "description": "Parser errors on last 3 runs",
  "component": "Layer 1 Scanner",
  "affected_competitors": ["Dabur"],
  "affected_sources": ["77f0…"],
  "scan_run_id": "a1b2c3d4-…"
}

    Response — 201 Created → the incident shape above.

    Status codes: 201 created · 400 title is required.

    PATCH /admin/observability/incidents/{incident_id}¶

    Update mutable incident fields. Setting status to resolved auto-populates resolved_at (once). Component: Observability. Backing code: app/admin/observability_routes.py → update_incident().

    Path parameters

    Name Type Description
    incident_id string (UUID) Incident.id.

    Request body — untyped dict; only these keys are applied (each optional): status, severity, root_cause, blast_radius, component, description.

    // Example request body
{ "status": "resolved", "root_cause": "ATS schema changed; parser updated" }

    Response — 200 OK → the incident shape above (with resolved_at now set).

    Status codes: 200 OK · 404 incident not found.

    Maintenance Actions¶

    Maintenance actions (MaintenanceAction) follow an approval lifecycle: pending_approval → approved → executed. Bodies are untyped dict.

    The action response shape (_serialize_action) is:

    Field Type Description
    id string (UUID) Action id.
    incident_id string (UUID)|null Linked incident.
    action_type string e.g. disable_source, rerun_layer2, switch_provider, review_manually.
    description string What the action does.
    parameters object From parameters_json.
    status enum pending_approval\|approved\|executed Lifecycle state.
    risk_level enum low\|medium\|high Risk classification.
    auto_executable bool Whether it can auto-run.
    requested_by string Requester (admin, copilot, …).
    approved_by string|null Set when approved.
    result object|null From result_json, set on execution.
    created_at datetime|null Creation time.
    executed_at datetime|null Execution time.

    GET /admin/observability/maintenance-actions¶

    List maintenance actions, newest first. Component: Observability. Backing code: app/admin/observability_routes.py → get_maintenance_actions().

    Query parameters

    Name Type Required Default Description
    incident_id string (UUID) no — Filter by linked incident.
    status string no — Filter by lifecycle status.
    limit int no 50 Max rows.

    Response — 200 OK → list[object] (each is the action shape above).

    // Example 200 response
[
  {
    "id": "b7a1…", "incident_id": "0f2b…", "action_type": "disable_source",
    "description": "Temporarily disable Dabur careers source", "parameters": {},
    "status": "pending_approval", "risk_level": "high", "auto_executable": false,
    "requested_by": "admin", "approved_by": null, "result": null,
    "created_at": "2026-07-09T05:10:00Z", "executed_at": null
  }
]

    Status codes: 200 OK.

    POST /admin/observability/maintenance-actions¶

    Create a maintenance action (starts pending_approval). Component: Observability. Backing code: app/admin/observability_routes.py → create_maintenance_action().

    Request body — untyped dict; keys the route reads:

    Field Type Required Default Description

    Copilot (LLM)¶

    POST /admin/observability/copilot¶

    Ops assistant. Assembles live context (system health, recent runs, 6h LLM metrics, problem sources, non-closed incidents, and any incident whose UUID appears in the question), asks the LLM for a structured diagnosis, and auto-creates a MaintenanceAction row for each recommended action (needs_approval: true → pending_approval, otherwise approved; no_action_needed is skipped, all requested_by: "copilot"). Component: Observability. Backing code: app/admin/observability_routes.py → maintenance_copilot().

    Request body — untyped dict:

    Field Type Required Default Description
    question string yes — Trimmed admin question; 400 if empty/missing. If it contains a UUID, the matching incident is surfaced into context. 
    // Example request body
{ "question": "Why is Dabur careers failing and what should I do?" }

    Response — 200 OK → hand-built dict

    Field Type Description
    question string Echoes the input.
    diagnosis object The LLM's structured output (see below).
    actions_created list[object] One {action_type, risk_level} per auto-created maintenance action.
    context_snapshot object {overall_status, active_incidents, problem_source_count} summarizing the context used.

    diagnosis object (validated against the copilot schema):

    Field Type Description
    status enum healthy\|degraded\|critical\|unknown Copilot's assessment.
    likely_root_cause string Most probable cause.
    evidence list[string] Supporting bullets.
    blast_radius string What is / isn't affected.
    recommended_actions list[object] See below.
    answer string Plain-English answer to the question.

    Each recommended_actions[] entry:

    Field Type Description
    description string Action description.
    action_type enum (disable_source\|rerun_layer2\|rebaseline_source\|switch_provider\|purge_dlq\|pause_competitor\|rollback_policy_pack\|adjust_scan_frequency\|inspect_artifact\|review_manually\|no_action_needed) Action kind.
    risk_level enum low\|medium\|high Risk.
    needs_approval bool Whether the created action starts pending_approval.
    verification_step string How to confirm it worked (stored in the created action's parameters.verification_step). 
    // Example 200 response (abbreviated)
{
  "question": "Why is Dabur careers failing and what should I do?",
  "diagnosis": {
    "status": "degraded",
    "likely_root_cause": "Dabur careers ATS markup changed, breaking the careers parser.",
    "evidence": [
      "3 consecutive parse_error failures on Dabur careers",
      "Other Dabur sources healthy",
      "No LLM provider errors in last 6h"
    ],
    "blast_radius": "Dabur careers signals only; other competitors and sources unaffected.",
    "recommended_actions": [
      {
        "description": "Disable Dabur careers source until parser is fixed",
        "action_type": "disable_source", "risk_level": "high",
        "needs_approval": true, "verification_step": "Confirm source is skipped in next scan."
      }
    ],
    "answer": "The Dabur careers ATS changed its markup. Disable the source and update the parser."
  },
  "actions_created": [ { "action_type": "disable_source", "risk_level": "high" } ],
  "context_snapshot": { "overall_status": "degraded", "active_incidents": 1, "problem_source_count": 3 }
}

    Status codes: 200 OK · 400 question is required · 500 LLM call failed or returned an invalid/missing-field response.

    Pipeline Board¶
