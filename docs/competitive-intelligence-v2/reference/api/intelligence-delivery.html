    API — Intelligence & Delivery¶

    This page documents the non-governance endpoints of the intelligence router (app/admin/intelligence_routes.py): scoring weights, agent configs, candidate signals and detected changes (including the feedback capture endpoint), competitor profiles, the LLM-backed query endpoint, delivery/digests, and the pipeline/Layer 2/scheduler triggers. The governance endpoints of the same router (proposals, policy packs, suppression/agent-policy rules, eval cases, NL command) are documented on the Feedback Governance & Policy Health page.

    Every endpoint here is exposed under the /admin prefix. All handlers use body: dict (untyped) request bodies and return hand-built dict / list[dict] payloads — there are no Pydantic response_models on this router, so the field tables below are taken directly from the route function bodies.

    No authentication

    These admin endpoints have no auth dependency. Do not expose the router on an untrusted network.

    Godrej Consumer Products grounding

    The Layer 2 pipeline and its LLM prompts are grounded in Godrej Consumer Products (GCP) as the home company; monitored competitors are HUL, P&G India, ITC, Marico, Dabur, and Reckitt. This shapes the so_what / impact_assessment output surfaced by the detected-change endpoints and the answer produced by the query endpoint.

    Scoring Weights¶

    A single ScoringWeightProfile is active at a time. Creating a profile does not auto-activate it. The active profile's weights_json is merged over the built-in DEFAULT_WEIGHTS key-by-key at the top level.

    GET /admin/scoring-weights¶

    List all scoring-weight profiles, newest first, flagging which one is active. Component: Scoring. Backing code: app/admin/intelligence_routes.py → list_scoring_weights().

    Response — 200 OK → list of profile objects

    Field Type Description
    id string (UUID) Profile id.
    name string Profile name.
    is_active bool Whether this is the active profile.
    created_by string Who created it.
    created_at string (datetime) | null Creation timestamp (stringified).
    updated_at string (datetime) | null Last-update timestamp.
    weights_json object The weight overrides for this profile.
    adjustment_log_json list[object] Audit log of weight adjustments applied to this profile. 
    // Example 200 response
[
  {
    "id": "9f3c1e20-…",
    "name": "q3-tuned",
    "is_active": true,
    "created_by": "krishna",
    "created_at": "2026-07-01 09:12:04",
    "updated_at": "2026-07-05 14:22:10",
    "weights_json": { "category_scores": { "Pricing Change": 20 } },
    "adjustment_log_json": [
      { "adjusted_by": "analyst", "verdict": "under_rated", "reason": "pricing under-weighted", "at": "2026-07-05T14:22:10" }
    ]
  }
]

    Status codes: 200.

    POST /admin/scoring-weights¶

    Create a new profile. It is created inactive (is_active=false); call the activate endpoint to make it live. Component: Scoring. Backing code: create_scoring_weight_profile().

    Request body — untyped dict; the route reads:

    Field Type Required Default Description
    name string no "default" Profile name.
    weights_json object no {} Weight overrides (same shape as GET /admin/scoring-weights/defaults).
    created_by string no "admin" Creator identifier. 
    // Example request body
{ "name": "q3-tuned", "weights_json": { "category_scores": { "Pricing Change": 20 } }, "created_by": "krishna" }

    Response — 201 Created

    Field Type Description
    id string (UUID) New profile id.
    name string Profile name.
    is_active bool Always false on create.
    created_by string Creator.
    created_at string (datetime) | null Creation timestamp.
    weights_json object The stored overrides. 
    // Example 201 response
{ "id": "9f3c1e20-…", "name": "q3-tuned", "is_active": false, "created_by": "krishna", "created_at": "2026-07-08 10:00:00", "weights_json": { "category_scores": { "Pricing Change": 20 } } }

    Status codes: 201.

    PUT /admin/scoring-weights/{profile_id}/activate¶

    Activate a profile, deactivating every other profile in the same call. Component: Scoring. Backing code: activate_scoring_weight_profile().

    Path parameters

    Name Type Description
    profile_id string (UUID) Profile to activate.

    Response — 200 OK

    Field Type Description
    id string (UUID) Activated profile id.
    name string Profile name.
    is_active bool true.
    message string "Profile activated successfully." 
    // Example 200 response
{ "id": "9f3c1e20-…", "name": "q3-tuned", "is_active": true, "message": "Profile activated successfully." }

    Status codes: 200 · 404 profile not found.

    PATCH /admin/scoring-weights/{profile_id}¶

    Merge weight updates into an existing profile and append a reason to its adjustment log. Delegates to app.intelligence.scoring_weights.update_weights(). Component: Scoring. Backing code: patch_scoring_weight_profile().

    Path parameters

    Name Type Description
    profile_id string (UUID) Profile to update.

    Request body — untyped dict. Two accepted shapes:

    Field Type Required Default Description
    weight_updates object no — Explicit map of weight keys → new values (old format).
    category_scores / tier_scores / any other weight key object no — New format: any top-level weight key not named adjusted_by/reason/weight_updates is collected into weight_updates.
    adjusted_by string no "admin" Who made the change (logged).
    reason string no "manual edit" Why (logged).

    At least one weight update must be present or the route returns 400.

    // Example request body (new format)
{ "category_scores": { "Pricing Change": 22 }, "adjusted_by": "krishna", "reason": "pricing signals were under-scored" }

    Response — 200 OK

    Field Type Description
    id string (UUID) Profile id.
    name string Profile name.
    is_active bool Active flag.
    weights_json object Merged weights after update.
    adjustment_log_json list[object] Full adjustment audit log.
    updated_at string (datetime) | null Update timestamp. 
    // Example 200 response
{ "id": "9f3c1e20-…", "name": "q3-tuned", "is_active": true, "weights_json": { "category_scores": { "Pricing Change": 22 } }, "adjustment_log_json": [ { "adjusted_by": "krishna", "reason": "pricing signals were under-scored" } ], "updated_at": "2026-07-08 10:05:00" }

    Status codes: 200 · 400 no weight updates provided · 404 profile not found (raised from update_weights ValueError).

    Agent Configs¶

    Per-agent prompt addenda and feedback used to steer LLM pipeline agents (AgentFeedbackConfig). Agents call get_prompt_addendum() at LLM-invocation time to append admin-supplied instructions to their system prompt.

    GET /admin/agent-configs¶

    List all agent configs, ordered by agent name. Component: Intelligence. Backing code: list_agent_configs().

    Response — 200 OK → list of config objects

    Field Type Description
    id string (UUID) Config row id.
    agent_name string Agent identifier (e.g. classifier, scorer, impact_analysis, relevance_filter).
    is_active bool Whether the config is active.
    prompt_addendum string Text appended to the agent's system prompt.
    config_json object Structured config, e.g. {"examples": [...]}.
    feedback_notes_json list[object] Recent feedback notes (each {type,text,by,at}).
    updated_by string | null Last editor.
    created_at / updated_at string (datetime) | null Timestamps. 
    // Example 200 response
[
  { "id": "a1…", "agent_name": "classifier", "is_active": true, "prompt_addendum": "Treat CSR press releases as low significance.", "config_json": {}, "feedback_notes_json": [ { "type": "instruction", "text": "Treat CSR press releases as low significance.", "by": "krishna", "at": "2026-07-02T11:00:00" } ], "updated_by": "krishna", "created_at": "2026-06-01 09:00:00", "updated_at": "2026-07-02 11:00:00" }
]

    Status codes: 200.

    GET /admin/agent-configs/{agent_name}¶

    Fetch one agent's config. Returns sensible defaults (empty strings/lists) when no row exists yet — this endpoint does not 404. Component: Intelligence. Backing code: get_agent_config() → app.intelligence.agent_feedback.get_agent_config().

    Path parameters

    Name Type Description
    agent_name string Agent identifier.

    Response — 200 OK

    Field Type Description
    agent_name string Echoed agent name.
    prompt_addendum string Current addendum ("" if none).
    config_json object Structured config ({} if none).
    feedback_notes list[object] Feedback notes ([] if none). 
    // Example 200 response
{ "agent_name": "scorer", "prompt_addendum": "", "config_json": {}, "feedback_notes": [] }

    Status codes: 200.

    POST /admin/agent-configs/{agent_name}/feedback¶

    Add a feedback item to an agent. instruction/constraint are appended to prompt_addendum; correction/example are appended to config_json["examples"]. All types are recorded in feedback_notes_json (capped to the most recent N). Component: Feedback governance. Backing code: submit_agent_feedback() → app.intelligence.agent_feedback.submit_agent_feedback().

    Path parameters

    Name Type Description
    agent_name string Agent to steer.

    Request body — untyped dict; the route reads:

    Field Type Required Default Description
    feedback_type enum instruction\|correction\|example\|constraint yes — How the feedback is applied.
    feedback_text string yes — The feedback content.
    submitted_by string no "admin" Submitter identifier. 
    // Example request body
{ "feedback_type": "instruction", "feedback_text": "Treat CSR press releases as low significance.", "submitted_by": "krishna" }

    Response — 201 Created

    Field Type Description
    id string (UUID) Config row id.
    agent_name string Agent name.
    is_active bool Active flag.
    prompt_addendum string Updated addendum.
    feedback_notes_json list[object] Recent notes including the new one.
    config_json object Updated config.
    updated_by string Submitter.
    updated_at string (datetime) | null Update timestamp. 
    // Example 201 response
{ "id": "a1…", "agent_name": "classifier", "is_active": true, "prompt_addendum": "Treat CSR press releases as low significance.", "feedback_notes_json": [ { "type": "instruction", "text": "Treat CSR press releases as low significance.", "by": "krishna", "at": "2026-07-08T10:10:00" } ], "config_json": {}, "updated_by": "krishna", "updated_at": "2026-07-08 10:10:00" }

    Status codes: 201 · 400 feedback_type missing, feedback_text missing, or feedback_type not in the allowed set (the underlying ValueError is surfaced as 400).

    POST /admin/detected-changes/{change_id}/feedback¶

    Submit an analyst verdict on a detected change. This is the main feedback capture / learning endpoint — a single call fans out to three subsystems:

    1. Legacy immediate path — records an AnalystFeedback row and applies structural side-effects via apply_feedback() (archive on false_positive, reset promoted signals to candidate on needs_reanalysis, URL suppression entries). Correction notes are pushed to the agents mapped to the verdict.
    2. Governance pipeline — FeedbackService.process_feedback() runs the same feedback through the proposal/policy governance flow (surfaced on the Feedback Governance page).
    3. LLM weight adjustment — for over_rated / under_rated / false_positive / missed with a non-empty reason, the score breakdown is loaded and an LLM decides which scoring weights to nudge via decide_weight_adjustments_with_llm() + apply_llm_weight_adjustments().

    Component: Feedback governance. Backing code: submit_change_feedback(); orchestration in app.intelligence.agent_feedback.FeedbackOrchestrator.process_change_feedback().

    Path parameters

    Name Type Description
    change_id string (UUID) Change being reviewed.

    Request body — untyped dict; the route reads exactly these keys:

    Field Type Required Default Description
    verdict enum (7 values, below) yes — Analyst verdict. Validated against the allowed set.
    reason string no "" Free-text rationale. Required to trigger the LLM weight-adjustment path.
    analyst string no "analyst" Analyst identifier (note: the key is analyst, not analyst_name).

    Allowed verdict values and their effects:

    Verdict Effect
    correct Records feedback; no structural change.
    false_positive Archives the change + creates URL suppression entries; governance suppression-rule proposal; LLM weight adjustment (if reason).
    low_priority Records feedback only.
    over_rated LLM weight adjustment (decrease) if reason; governance proposal.
    under_rated LLM weight adjustment (increase) if reason; governance proposal.
    needs_reanalysis Resets promoted signals to candidate; marks the change needs_reanalysis.
    missed Records a false-negative; LLM weight adjustment if reason. 
    // Example request body
{ "verdict": "over_rated", "reason": "This launch is regional only, not national.", "analyst": "krishna" }

    Response — 201 Created. The body is the process_change_feedback() result dict, augmented in-place by the route:

    Field Type Description
    change_id string (UUID) Echoed change id.
    feedback_id string (UUID) | null Created AnalystFeedback id (null if recording failed).
    weight_adjustment object | null Result of the weight adjustment. For LLM verdicts: {adjusted, profile_id, adjustments} on success, or {adjusted: false, error} on failure; for heuristic verdicts deferred to the LLM path this may read {adjusted: false, reason: "deferred_to_llm"}.
    agent_configs_updated list[string] Agent names that received a correction note.
    apply_notes list[string] Notes from the structural apply_feedback() step (present when a feedback row was created). 
    // Example 201 response
{
  "change_id": "dc-101",
  "feedback_id": "fb-2",
  "weight_adjustment": { "adjusted": true, "profile_id": "9f3c…", "adjustments": [ { "path": "category_scores.Product Launch", "delta": -3 } ] },
  "agent_configs_updated": ["scorer"],
  "apply_notes": ["No structural action for verdict over_rated"]
}

    Status codes: 201 · 400 verdict missing · 404 change not found · 422 verdict not in the allowed set of 7 (detail lists the valid values).

    Competitor Profiles¶

    Query (LLM)¶

    POST /admin/query¶

    Natural-language Q&A over competitor profiles and detected changes, via QueryService (prompt competitor_query v2). When competitor is provided the question is scoped to that competitor; otherwise the service either auto-detects a single competitor named in the question or runs one combined call across all active competitors that have profiles. Component: Intelligence. Backing code: query_intelligence() → app/intelligence/query_service.py.

    Request body — untyped dict; the route reads:

    Field Type Required Default Description
    question string yes — The natural-language question.
    competitor string no null Competitor id or name to scope the query. 
    // Example request body
{ "question": "What pricing moves has HUL made recently?", "competitor": "HUL" }

    Response — 200 OK. The shape depends on whether competitor was provided.

    A. competitor provided (or the question clearly targets one competitor) → a single answer object:

    Field Type Description
    competitor / competitor_name string Target competitor (or "All competitors").
    question string Echoed question.
    answer string The LLM answer (never empty; falls back to a placeholder).
    key_events list[object] Each {competitor, event, significance}.
    sources list[string] Source URLs (LLM-selected, else collected from changes).
    confidence enum high\|medium\|low Answer confidence.
    gaps string Noted data gaps. 
    // Example 200 response (competitor provided)
{
  "competitor": "HUL", "competitor_name": "HUL",
  "question": "What pricing moves has HUL made recently?",
  "answer": "HUL cut entry-tier detergent prices ~5% while launching a premium range …",
  "key_events": [ { "competitor": "HUL", "event": "Premium detergent launch", "significance": "high" } ],
  "sources": ["https://example.com/hul-launch"],
  "confidence": "high", "gaps": "No margin data available."
}

    B. competitor omitted (broad query) → a wrapper object:

    Field Type Description
    question string Echoed question.
    results list[object] List of answer objects (same shape as A; usually length 1 — one combined answer).
    count int len(results). 
    // Example 200 response (broad query)
{
  "question": "Which competitors expanded distribution this quarter?",
  "results": [
    { "competitor": "All competitors", "competitor_name": "All competitors", "question": "Which competitors expanded distribution this quarter?", "answer": "Marico and Dabur both …", "key_events": [], "sources": [], "confidence": "medium", "gaps": "" }
  ],
  "count": 1
}

    Status codes: 200 · 400 question is required.
