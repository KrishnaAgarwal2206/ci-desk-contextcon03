    API — Feedback Governance & Policy Health¶

    This page documents the governance endpoints of the intelligence router (app/admin/intelligence_routes.py, all under /admin/feedback/*) and the policy-health router (app/admin/policy_health_routes.py, under /admin/policy-health/*). These endpoints drive the human-review governance lifecycle: legacy suppressions, proposals, policy packs, patterns, rules, evaluation, weight profiles, runtime state, and the policy-health snapshot/consolidation tools. See Concepts: Feedback & Learning for the model.

    Every endpoint below takes and returns hand-built dict payloads — none use a Pydantic response_model, and request bodies are untyped dict (the route reads specific keys, documented per endpoint). Timestamps are ISO 8601 strings. IDs are UUID strings.

    Two suppression systems, not unified

    Legacy FeedbackSuppressionEntry (Layer 1, enforced in the scan worker and news analyzer) and governance SuppressionRule (Layer 2, enforced in the orchestrator) are separate tables. The /admin/feedback/suppressions endpoints below manage the legacy table; governance SuppressionRule rows are created via proposal approval or the NL command.

    Governance pipeline is deterministic

    Feature extraction, pattern mining, and proposal generation use no LLM. LLM is used only in the legacy weight-adjustment decision, natural-language command parsing (POST /admin/feedback/nl-command), policy consolidation (POST /admin/policy-health/{pack_id}/consolidate), and eval runs of LLM agents.

    Budget constants

    Defined in app/feedback/policy_compiler.py: per-pack token budget MAX_POLICY_PACK_TOKENS = 400, per-run token budget MAX_AGENT_POLICY_TOKENS_PER_RUN = 800, max MAX_RULES_PER_PACK = 8 rules per pack, max MAX_POLICY_PACKS_PER_AGENT_RUN = 5 packs per agent run, near-budget warning at 0.80 utilisation. Token estimate ≈ 1.3 tokens/word (_estimate_tokens).

    Suppressions (legacy)¶

    Manages FeedbackSuppressionEntry rows (Layer 1 suppressions).

    GET /admin/feedback/suppressions¶

    List legacy suppression entries, newest first. Component: Feedback governance. Backing code: app/admin/intelligence_routes.py → list_feedback_suppressions().

    Query parameters

    Name Type Required Default Description
    active_only bool no true When true, only rows with is_active = true are returned.
    limit int no 200 Maximum rows returned.

    Response — 200 OK → list[object]

    Field Type Description
    id string (UUID) Entry id.
    suppression_type string The entry's entry_type (e.g. url, domain).
    suppression_value string The suppressed value.
    reason string | null Why it was suppressed.
    expires_at datetime | null Expiry timestamp, if set.
    created_at datetime | null Creation timestamp. 
    // Example 200 response
[
  {
    "id": "a1b2c3d4-0000-4a1b-9c2d-000000000001",
    "suppression_type": "url",
    "suppression_value": "https://example.com/press/boilerplate",
    "reason": "Recurring boilerplate press page",
    "expires_at": null,
    "created_at": "2026-07-01T09:12:44"
  }
]

    Status codes: 200 OK.

    POST /admin/feedback/suppressions¶

    Manually create a legacy FeedbackSuppressionEntry. Idempotent on (entry_type, value) for active rows. Component: Feedback governance. Backing code: app/admin/intelligence_routes.py → create_suppression().

    Request body — untyped dict

    Field Type Required Default Description
    value string yes — The value to suppress. Trimmed; empty → 400.
    entry_type string no "url" Suppression type (e.g. url, domain). 
    // Example request body
{ "value": "https://example.com/press/boilerplate", "entry_type": "url" }

    Response — 201 Created → object. Two shapes:

    If an identical active entry already exists (no new row created):

    Field Type Description
    id string (UUID) Existing entry id.
    created bool Always false in this branch.
    message string "Suppression already exists".

    Otherwise (new row created):

    Field Type Description
    id string (UUID) New entry id.
    entry_type string Stored type.
    value string Stored value.
    is_active bool true. 
    // Example 201 response (new entry)
{
  "id": "a1b2c3d4-0000-4a1b-9c2d-000000000009",
  "entry_type": "url",
  "value": "https://example.com/press/boilerplate",
  "is_active": true
}

    Status codes: 201 created (both branches use the 201 status) · 400 value missing.

    DELETE /admin/feedback/suppressions/{entry_id}¶

    Soft-delete a legacy suppression by setting is_active = false. Component: Feedback governance. Backing code: app/admin/intelligence_routes.py → deactivate_suppression().

    Path parameters

    Name Type Description
    entry_id string (UUID) Entry to deactivate.

    Response — 200 OK → object

    Field Type Description
    id string (UUID) The entry id.
    deactivated bool Always true on success. 
    // Example 200 response
{ "id": "a1b2c3d4-0000-4a1b-9c2d-000000000009", "deactivated": true }

    Status codes: 200 deactivated (soft-delete) · 404 entry not found.

    Proposals¶

    Governance proposals (FeedbackChangeProposal) sit in pending_human_review until approved or rejected. Approval always activates the proposal regardless of risk_level.

    GET /admin/feedback/proposals¶

    List change proposals, newest first. Component: Feedback governance. Backing code: app/admin/intelligence_routes.py → list_proposals().

    Query parameters

    Name Type Required Default Description
    status string no — Filter by status (e.g. pending_human_review, approved, edited_and_approved, rejected).
    limit int no 50 Maximum rows returned.

    Response — 200 OK → list[object]

    Field Type Description
    id string (UUID) Proposal id.
    proposal_type enum suppression_rule\|scoring_weight_change\|agent_policy_rule What the proposal would activate.
    target_agent string | null Agent the change targets (for policy-rule proposals).
    status string Lifecycle status.
    risk_level string low / medium / high (informational only; does not gate approval).
    reasoning string | null Why the pipeline proposed this.
    proposed_change object The proposed_change_json payload.
    created_at datetime | null Creation timestamp. 
    // Example 200 response
[
  {
    "id": "prop-0001-4a1b-9c2d-000000000001",
    "proposal_type": "agent_policy_rule",
    "target_agent": "classifier",
    "status": "pending_human_review",
    "risk_level": "low",
    "reasoning": "3 analyst corrections about mislabeling distributor news as Partnership.",
    "proposed_change": {
      "agent_name": "classifier",
      "rule_text": "Do not classify routine distributor appointments as Partnership / Acquisition.",
      "scope": { "category": "Partnership / Acquisition" },
      "priority": 60
    },
    "created_at": "2026-07-06T14:03:21"
  }
]

    Status codes: 200 OK.

    POST /admin/feedback/proposals/{proposal_id}/approve¶

    Approve a proposal and immediately activate it. Only pending_human_review proposals are approvable. Component: Feedback governance. Backing code: app/admin/intelligence_routes.py → approve_proposal() → HumanReviewService.approve_proposal().

    Path parameters

    Name Type Description
    proposal_id string (UUID) Proposal to approve.

    Request body — untyped dict

    Field Type Required Default Description
    reviewer string no "admin" Recorded as reviewed_by.
    edited_change_json object no — If supplied, replaces proposed_change_json and sets status to edited_and_approved (otherwise approved). Activation then uses the edited payload.

    Activation effect by proposal_type:

    • suppression_rule → creates one governance SuppressionRule per entry in all_values (falls back to a single value); skips values that already have an active rule.
    • scoring_weight_change → supersedes the active ScoringWeightProfile and creates a new active profile with the changed category weight.
    • agent_policy_rule → creates an active AgentPolicyRule for target_agent, then auto-recompiles that agent's default policy pack.
    // Example request body (approve with an edit)
{
  "reviewer": "krishna",
  "edited_change_json": {
    "agent_name": "classifier",
    "rule_text": "Never classify distributor onboarding as Partnership / Acquisition.",
    "scope": { "category": "Partnership / Acquisition" },
    "priority": 55
  }
}

    Response — 200 OK → object

    Field Type Description
    proposal_id string (UUID) The proposal id.
    status string approved or edited_and_approved.
    activated list[object] Objects created/activated; each has type plus type-specific keys (id, value, category, agent, tokens, …). 
    // Example 200 response
{
  "proposal_id": "prop-0001-4a1b-9c2d-000000000001",
  "status": "edited_and_approved",
  "activated": [
    { "type": "agent_policy_rule", "id": "rule-77a1-...-01", "agent": "classifier" },
    { "type": "compiled_policy_pack", "id": "pack-9f0c-...-02", "agent": "classifier", "tokens": 214, "auto_recompiled": true }
  ]
}

    Status codes: 200 approved · 400 proposal not found, or not in pending_human_review (both surface via the error field mapped to 400).

    POST /admin/feedback/proposals/{proposal_id}/reject¶

    Reject a proposal with optional review notes. Component: Feedback governance. Backing code: app/admin/intelligence_routes.py → reject_proposal() → HumanReviewService.reject_proposal().

    Path parameters

    Name Type Description
    proposal_id string (UUID) Proposal to reject.

    Request body — untyped dict

    Field Type Required Default Description
    reviewer string no "admin" Recorded as reviewed_by.
    notes string no "" Stored as review_notes. 
    // Example request body
{ "reviewer": "krishna", "notes": "Too broad — would suppress legitimate JV news." }

    Response — 200 OK → object

    Field Type Description
    proposal_id string (UUID) The proposal id.
    status string Always rejected. 
    // Example 200 response
{ "proposal_id": "prop-0001-4a1b-9c2d-000000000001", "status": "rejected" }

    Status codes: 200 rejected · 400 proposal not found.

    List policy packs, newest first. Component: Feedback governance. Backing code: app/admin/intelligence_routes.py → list_policy_packs().

    Query parameters

    Name Type Required Default Description
    agent_name string no — Filter to one agent.

    Response — 200 OK → list[object]

    Field Type Description
    id string (UUID) Pack id.
    agent_name string Owning agent.
    pack_name string Pack name (e.g. default).
    version string Version label (prefix + counter).
    status enum draft\|active\|superseded\|budget_exceeded Lifecycle status.
    token_estimate int Estimated tokens in compiled_text.
    created_at datetime | null Creation timestamp. 
    // Example 200 response
[

    "pack_name": "default",

    "status": "active",
    "token_estimate": 214,
    "created_at": "2026-07-06T14:05:00"
  }
]

    Status codes: 200 OK.

    POST /admin/feedback/policy-packs/compile¶

    Compile a new policy pack. Supersedes any active pack with the same agent_name + pack_name. Newly compiled packs start in draft (or budget_exceeded, all-active mode only) and must be activated separately. Component: Feedback governance. Backing code: app/admin/intelligence_routes.py → compile_policy_pack() (and PolicyCompiler.compile_pack() for all-active mode).

    Request body — untyped dict. The route picks one of three modes by which key is present:

    Common fields (all modes):

    Field Type Required Default Description
    agent_name string no "unknown" Owning agent.
    pack_name string no "default" Pack name.
    scope_json object no {} Free-form scope metadata stored on the pack.

    Mode-specific fields:

    Field Type Mode Description
    custom_text string custom_text Fully hand-written pack text. When present, rule lookup is skipped; included_policy_rule_ids_json is []. Empty string → text becomes "(empty pack)". Status is always draft (no budget downgrade).
    rule_ids list[string (UUID)] rule_ids Explicit rule ids; compiled as a numbered list in the given order (unknown ids dropped). Status is always draft.
    reviewer string all-active (default) Used only when neither custom_text nor rule_ids is present. Compiles all active rules for agent_name in priority order, capped at min(settings.MAX_POLICY_RULES_PER_PACK, 8). Status becomes budget_exceeded if the estimate exceeds 400, else draft. Defaults to "admin". 

    // Example request body — custom_text mode
{ "agent_name": "classifier", "pack_name": "default", "custom_text": "1. Prefer Regulatory / Legal over Product Launch when a recall is mentioned." }

    // Example request body — rule_ids mode
{ "agent_name": "classifier", "pack_name": "default", "rule_ids": ["rule-77a1-...-01", "rule-77a1-...-04"] }

    // Example request body — all-active mode
{ "agent_name": "classifier", "pack_name": "default", "reviewer": "krishna" }

    Response — 200 OK → object (identical across all three modes)

    Field Type Description
    id string (UUID) New pack id.
    version string Version label.
    token_estimate int Estimated tokens.
    status enum draft\|budget_exceeded New pack status. 
    // Example 200 response
{ "id": "pack-9f0c-4a1b-9c2d-000000000010", "version": "v4", "token_estimate": 41, "status": "draft" }

    Status codes: 200 compiled (no explicit 201).

    PATCH /admin/feedback/policy-packs/{pack_id}¶

    Edit a pack's text, name, or included-rule id list. Editing compiled_text recomputes token_estimate. Component: Feedback governance. Backing code: app/admin/intelligence_routes.py → update_policy_pack().

    Path parameters

    Name Type Description
    pack_id string (UUID) Pack to edit.

    Request body — untyped dict (all optional; only keys present are applied)

    Field Type Required Default Description
    compiled_text string no — New pack text; recomputes token_estimate.
    pack_name string no — New name.
    included_policy_rule_ids_json list[string (UUID)] no — Replace the included-rule id list. 
    // Example request body
{ "compiled_text": "1. Prefer Regulatory / Legal over Product Launch when a recall is mentioned.\n2. Ignore reseller listings." }

    Response — 200 OK → object

    Field Type Description
    id string (UUID) Pack id.
    pack_name string Current name.
    token_estimate int Recomputed estimate.
    status string Unchanged pack status.
    compiled_text string Current pack text. 
    // Example 200 response
{
  "id": "pack-9f0c-4a1b-9c2d-000000000010",
  "pack_name": "default",
  "token_estimate": 63,
  "status": "draft",
  "compiled_text": "1. Prefer Regulatory / Legal over Product Launch when a recall is mentioned.\n2. Ignore reseller listings."
}

    Status codes: 200 updated · 404 pack not found.

    POST /admin/feedback/policy-packs/{pack_id}/activate¶

    Activate a draft pack after passing budget checks. Component: Feedback governance. Backing code: app/admin/intelligence_routes.py → activate_policy_pack() → PolicyCompiler.activate_pack().

    Path parameters

    Name Type Description
    pack_id string (UUID) Pack to activate.

    Request body — untyped dict

    Field Type Required Default Description
    reviewer string no "admin" Recorded as approved_by.

    Activation is blocked (raises, mapped to 404 — see status codes) if any check fails: token estimate > 400, rule count > 8, or duplicate rules detected (first 60 chars of two rules match). On success, status becomes active, activated_at is set, and a fresh health snapshot is written.

    // Example request body
{ "reviewer": "krishna" }

    Response — 200 OK → object

    Field Type Description
    id string (UUID) Pack id.
    status string active on success. 
    // Example 200 response
{ "id": "pack-9f0c-4a1b-9c2d-000000000010", "status": "active" }

    Status codes: 200 activated · 404 pack not found or activation blocked by budget/rule-count/duplicate checks (the route maps the compiler's ValueError to 404 for both cases; the error detail carries the blocking reasons).

    GET /admin/feedback/policy-packs/{pack_id}¶

    Fetch one pack with its expanded included rules. Component: Feedback governance. Backing code: app/admin/intelligence_routes.py → get_policy_pack().

    Path parameters

    Name Type Description
    pack_id string (UUID) Pack to fetch.

    Response — 200 OK → object

    Field Type Description
    id string (UUID) Pack id.
    agent_name string Owning agent.
    pack_name string Pack name.
    version string Version label.
    status string Lifecycle status.
    compiled_text string Full compiled pack text.
    token_estimate int Estimated tokens.
    included_rules list[object] Expanded rules: {id, rule_text, scope, status}.
    approved_by string | null Reviewer who activated it.
    created_at datetime | null Creation timestamp.
    activated_at datetime | null Activation timestamp. 
    // Example 200 response
{
  "id": "pack-9f0c-4a1b-9c2d-000000000002",
  "agent_name": "classifier",
  "pack_name": "default",
  "version": "v3",
  "status": "active",
  "compiled_text": "1. Do not classify routine distributor appointments as Partnership / Acquisition.",
  "token_estimate": 214,
  "included_rules": [
    { "id": "rule-77a1-...-01", "rule_text": "Do not classify routine distributor appointments as Partnership / Acquisition.", "scope": { "category": "Partnership / Acquisition" }, "status": "active" }
  ],
  "approved_by": "krishna",
  "created_at": "2026-07-06T14:05:00",
  "activated_at": "2026-07-06T14:07:11"
}

    Status codes: 200 OK · 404 pack not found.

    Patterns¶

  }
]

    Status codes: 200 OK.

    GET /admin/feedback/agent-policy-rules/all¶

    List agent policy rules of any status, ordered by agent then priority. Component: Feedback governance. Backing code: app/admin/intelligence_routes.py → list_all_agent_policy_rules().

    Query parameters

    Name Type Required Default Description
    agent_name string no — Filter to one agent.
    status string no — Filter by status (e.g. active, inactive).

    Response — 200 OK → list[object]

    Field Type Description
    id string (UUID) Rule id.
    agent_name string Owning agent.
    rule_text string Instruction text.
    scope object scope_json.
    priority int Priority.
    status string Rule status.
    approved_by string | null Approver.
    source_proposal_id string (UUID) | null Proposal that created it, if any.
    created_at datetime | null Creation timestamp.

    NL Command (LLM)¶

    POST /admin/feedback/nl-command¶

    Parse a free-text governance command with the LLM and execute it immediately. Component: Feedback governance. Backing code: app/admin/intelligence_routes.py → nl_governance_command().

    Request body — untyped dict

    Field Type Required Default Description
    command string yes — Free-text instruction. Trimmed; empty → 400.
    analyst string no "admin" Attribution for created rows.

    The LLM parses command into one of: add_rule, suppress, adjust_weight, compile_pack, deactivate_rule, query. The route then executes:

    • add_rule → creates an active AgentPolicyRule directly (not a proposal).
    • suppress → creates an active governance SuppressionRule directly.
    • adjust_weight → supersedes the active profile and creates a new active ScoringWeightProfile with the adjusted category value (only if the category currently exists).
    • compile_pack → recompiles the agent's pack via PolicyCompiler.
    • deactivate_rule → sets matching active rules to inactive (by keyword + optional agent filter).
    • query → no side effects.

    No proposal is created

    Despite the parser's own requires_approval hint, all actions execute directly. proposals_created is always [].

    // Example request body
{ "command": "Make the classifier stop tagging distributor appointments as partnerships", "analyst": "krishna" }

    Response — 200 OK → object

    Field Type Description
    command string Echoed command.
    action_type enum add_rule\|suppress\|adjust_weight\|compile_pack\|deactivate_rule\|query Parsed action.
    human_summary string LLM one-line summary of the action.
    executed list[object] Objects created/changed; each has type plus type-specific keys.
    proposals_created list Always empty. 
    // Example 200 response
{
  "command": "Make the classifier stop tagging distributor appointments as partnerships",
  "action_type": "add_rule",
  "human_summary": "Add a classifier rule to not label distributor appointments as Partnership / Acquisition.",
  "executed": [ { "type": "agent_policy_rule", "id": "rule-77a1-...-12", "agent": "classifier" } ],
  "proposals_created": []
}

    Status codes: 200 OK · 400 command missing · 500 LLM parse failed or execution failed.
