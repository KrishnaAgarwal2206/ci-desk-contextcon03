    API — Schedules & News Profiles¶

    This page documents the schedule router (app/admin/schedule_routes.py) and the news-profile router (app/admin/news_profile_routes.py). Schedules control when a source is due to scan; news profiles carry the rich per-competitor configuration used by the news adapter's query planner and relevance gate, with full versioning and two dry-run helpers. Schemas are in app/schemas/admin.py.

    Scheduling guardrails

    Enforced constants in schedule_routes.py: MIN_FREQUENCY_MINUTES = 30, MAX_QUERY_BUDGET = 20, MAX_PAGES = 50, MAX_CONCURRENT_SCANS = 10. On every create/update the route calls _compute_next_run(schedule), which sets next_run_at by schedule_type: manual → null; hourly → now + max(frequency_minutes or 60, 30) min; daily → now + 1 day; weekly → now + 7 days; cron → next fire of cron_expression via croniter (falling back to now + 24h if the expression is invalid).

    Schedules¶

    Each source has at most one SourceSchedule. Creating or updating a schedule computes next_run_at and writes an audit-log entry (object_type="schedule").

    GET /admin/sources/{source_id}/schedule¶

    Fetch the schedule for a single source. Component: Control plane, and Backing code: app/admin/schedule_routes.py → get_source_schedule().

    Path parameters

    Name Type Description
    source_id string (UUID) ID of the source whose schedule to fetch.

    Response — 200 OK → ScheduleOut

    Field Type Description
    id string (UUID) Schedule ID.
    source_id string (UUID) Owning source.
    schedule_type enum manual\|hourly\|daily\|weekly\|cron How the next run is computed.
    cron_expression string | null Cron string, used only when schedule_type="cron".
    frequency_minutes int | null Interval in minutes, used only when schedule_type="hourly".
    timezone string IANA timezone (e.g. Asia/Kolkata).
    preferred_time string | null "HH:MM" preferred fire time.
    days_of_week_json list[int] Days of week (0–6) for weekly schedules.
    jitter_minutes int Random spread added to scheduling.
    enabled bool Whether the schedule is active.
    next_run_at datetime (ISO 8601) | null Computed next fire time (null for manual).
    last_run_at datetime (ISO 8601) | null Last time the schedule fired.
    created_at datetime (ISO 8601) Creation timestamp.
    updated_at datetime (ISO 8601) Last-update timestamp.

    News Profiles¶

    A CompetitorNewsProfile is a rich, versioned configuration object for one competitor's news monitoring. Each competitor has at most one profile. Create/update/rollback all snapshot the resulting state into a ProfileVersion and write an audit entry (object_type="news_profile").

    The three JSON fields below carry nested object shapes used by the query planner and relevance gate:

    • aliases_json — list[object], each item { "alias": string, "requires_context": bool, "required_context_terms": list[string] }. When requires_context is true, an alias only counts as a match if one of required_context_terms also appears.
    • brands_json — list[object], each item { "brand": string, "requires_company_context": bool, "required_terms": list[string], "active": bool }. Inactive brands are ignored; requires_company_context gates the brand on company mentions.
    • leaders_json — list[object], each item { "name": string, "role": string, "active": bool }.
    • exclusion_rules_json — list[object] of free-form rule dicts consumed by the relevance gate.
    • query_config_json — object; keys read by the planner include include_brand_queries (bool, default true), include_leader_queries (bool, default true), include_official_domain_queries (bool, default true).
    • relevance_config_json / source_trust_json — free-form object tuning dicts.

    PATCH /admin/competitors/{competitor_id}/news-profile¶

    Update a competitor's news profile. Only non-null fields are applied; a new ProfileVersion is snapshotted at updated.current_version and an update audit entry with a before/after diff is written. Component: Intelligence, and Backing code: app/admin/news_profile_routes.py → update_news_profile().

    Path parameters

    Name Type Description
    competitor_id string (UUID) Competitor whose profile to update.

    Request body — schema NewsProfileUpdate (app/schemas/admin.py) — all NewsProfileCreate fields are present and optional (null = leave unchanged), plus:

    Field Type Required Default Description
    updated_by string | null no null Updater identity; used as the new version's changed_by (falls back to "admin").
    change_reason string | null no null Free-text reason; stripped from the profile payload and stored as the version's change_reason in the version log.

    Every other field is the optional (null-defaulted) counterpart of the matching NewsProfileCreate field above. Note created_by is not part of the update schema.

    // Example request body
{
  "strategic_keywords_json": ["price hike", "rural demand", "GST"],
  "leaders_json": [
    { "name": "Rohit Jawa", "role": "CEO & Managing Director", "active": true },
    { "name": "Ritesh Tiwari", "role": "CFO", "active": true }
  ],
  "updated_by": "krishna",
  "change_reason": "Added CFO to leaders and GST keyword"
}

    Response — 200 OK → NewsProfileOut (see field table under GET .../news-profile), with current_version incremented.

    Status codes: 200 OK · 404 no news profile for this competitor · 422 validation error.

    Versioning¶

    Every create, update, and rollback appends a ProfileVersion snapshot. These endpoints read the version history and restore prior snapshots.

    GET /admin/competitors/{competitor_id}/news-profile/versions¶

    List profile version snapshots, newest first. Component: Intelligence, and Backing code: app/admin/news_profile_routes.py → list_profile_versions().

    Path parameters

    Name Type Description
    competitor_id string (UUID) Competitor whose version history to list.

    Query parameters

    Name Type Required Default Description
    limit int no 20 Maximum number of versions to return.

    Response — 200 OK → list[ProfileVersionOut]

    Field Type Description
    id string (UUID) Version snapshot ID.
    competitor_id string (UUID) Owning competitor.
    profile_type string Always "news" for these endpoints.
    version_number int Sequential version number.
    changed_by string Identity that produced this version.
    change_reason string | null Reason recorded for the change.
    profile_json object Full snapshot of the profile at this version (all NewsProfileOut columns).
    is_rollback bool true if this version was produced by a rollback.
    created_at datetime (ISO 8601) When the snapshot was taken.

    POST /admin/competitors/{competitor_id}/news-profile/rollback/{version_id}¶

    Restore the live profile to a prior version's snapshot. Snapshot keys id, competitor_id, created_at, updated_at, current_version, created_by, updated_by are skipped; the rest overwrite the live profile. A new ProfileVersion is recorded with is_rollback=true and rolled_back_from_version set, and a rollback audit entry is written. Component: Intelligence, and Backing code: app/admin/news_profile_routes.py → rollback_to_version().

    Path parameters

    Name Type Description
    competitor_id string (UUID) Competitor whose profile to roll back.
    version_id string (UUID) Version snapshot to restore; must belong to this competitor.

    Response — 200 OK → NewsProfileOut (the restored, re-versioned profile; see field table under GET .../news-profile).

    // Example 200 response
{
  "id": "7d2f9a10-4c3b-4e51-9a22-1b2c3d4e5f60",
  "competitor_id": "3a1b2c3d-4e5f-4061-8273-9a0b1c2d3e4f",
  "display_name": "Hindustan Unilever",
  "short_name": "HUL",
  "current_version": 4,
  "is_active": true,
  "updated_by": "admin",
  "updated_at": "2026-07-09T10:40:00"
}

    Status codes: 200 OK · 404 version not found or not owned by this competitor, or no active profile to roll back.

    GET /admin/competitors/{competitor_id}/news-profile/preview-queries¶

    Preview the search queries the query planner would generate for a competitor. If a news profile exists, uses build_queries_from_profile; otherwise falls back to the competitor's basic fields via build_queries. Component: Intelligence, and Backing code: app/admin/news_profile_routes.py → preview_queries() (planner in app/adapters/news/query_planner.py).

    Path parameters

    Name Type Description
    competitor_id string (UUID) Competitor to preview queries for.

    Query parameters

    Name Type Required Default Description
    budget int no 10 Maximum number of queries the planner may emit.

    Response — 200 OK → hand-built dict. Shape depends on whether a profile exists:

    Field Type Description
    source enum news_profile\|competitor_fields news_profile when built from the profile; competitor_fields on fallback.
    profile_version int Present only when source="news_profile"; the profile's current_version.
    queries list[string] Generated search-query strings.
    count int Length of queries. 
    // Example 200 response (profile present)
{
  "source": "news_profile",

    "Rohit Jawa Hindustan Unilever",

{
  "source": "competitor_fields",
  "queries": ["Hindustan Unilever", "HUL"],
  "count": 2
}

    Status codes: 200 OK · 404 competitor not found (only reachable on the fallback path when the competitor itself is missing).

    POST /admin/competitors/{competitor_id}/news-profile/test-relevance¶

    Run one sample article through the relevance gate and return its decision. If an active profile exists, uses profile_relevance_check; otherwise uses fast_relevance_check against the competitor's own fields and maps its verdict (strong_relevant→pass, borderline→llm_review, else suppress). Component: Feedback governance, and Backing code: app/admin/news_profile_routes.py → test_relevance() (gate in app/analysis/news/relevance.py).

    Path parameters

    Name Type Description
    competitor_id string (UUID) Competitor whose relevance rules to apply.

    Request body — untyped dict; the route reads these keys:

    Field Type Required Default Description
    title string no "" Article headline.
    snippet string no "" Article summary/snippet.
    url string no "" Article URL (used for domain checks). 
    // Example request body
{
  "title": "Hindustan Unilever raises detergent prices amid rural slowdown",
  "snippet": "HUL announced a price hike across its Surf Excel range citing input costs.",
  "url": "https://economictimes.indiatimes.com/industry/cons-products/hul-price-hike"
}

    Response — 200 OK → hand-built dict.

    Field Type Description
    decision enum pass\|suppress\|llm_review Gate outcome.
    reasons list[string] Human-readable reasons behind the decision. 
    // Example 200 response
{
  "decision": "pass",
  "reasons": [
    "matched display_name 'Hindustan Unilever' in title",
    "matched brand 'Surf Excel' in snippet",
    "matched strategic keyword 'price hike'"
  ]
}

    Status codes: 200 OK · 404 competitor not found.
