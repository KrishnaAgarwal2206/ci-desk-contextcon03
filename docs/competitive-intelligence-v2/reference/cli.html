    CLI Reference¶

    The ci-agent command-line interface is a Typer application defined in app/cli.py. It is the primary way to run scans, drive the Layer 2 pipeline, submit feedback, tune scoring, and deliver digests outside the web admin panel. Every command below is listed with its exact name, purpose, key flags, and an example invocation.

    Invocation¶

    The console entry point ci-agent (declared in pyproject.toml as ci-agent = "app.cli:app") is exactly equivalent to python -m app.cli. Both forms accept the same commands and flags:

    ci-agent <command> [OPTIONS]
python -m app.cli <command> [OPTIONS]   # identical

    Command names use hyphens (Typer converts the underscored function names, e.g. init_db → init-db). Run ci-agent --help for the generated catalog, or ci-agent <command> --help for a command's flags.

    Note

    Most commands open their own database session against DATABASE_URL and close it on exit. The server does not need to be running for CLI commands to work — they operate directly on the database and infrastructure factories.

    Setup & database¶

    Command Purpose Key flags Example
    init-db Initialize the schema. Default runs Base.metadata.create_all plus _safe_add_columns; --alembic runs alembic upgrade head instead. --alembic ci-agent init-db
    load-config Load competitors and sources from a YAML config file via app/admin/yaml_loader.py. CONFIG_PATH (positional, required) ci-agent load-config examples/config/godrej_competitors.yaml

    Warning

    load-config always inserts — it performs no upsert or de-duplication. Re-running it on the same YAML creates duplicate competitors and sources.

    Layer 1 — scanning & inspection¶

    Command Purpose Key flags Example
    schedule-once Enqueue all due active sources into the queue (creates a ScanRun, does not process). — ci-agent schedule-once
    worker-once Schedule due sources, then drain the queue with SourceScanWorker.run_until_empty(). — ci-agent worker-once
    dev-run-once Canonical local run: schedule + worker + printed summary table (artifacts, docs, items, deltas, packages, signals, LLM calls) for the scan run. — ci-agent dev-run-once
    status Show what is stored per competitor/source (items, artifacts, last scan). — ci-agent status
    list-scan-runs List recent scan runs with status and counts. --limit (default 10) ci-agent list-scan-runs --limit 20
    list-candidate-signals List recent CandidateSignal rows (Layer 1 output). --limit (30), --verbose/-v, --status, --type ci-agent list-candidate-signals -v --status candidate
    show-signal Show full detail for one signal including its ChangePackage, evidence, and LLM trace. SIGNAL_ID (positional, required) ci-agent show-signal <signal-id>
    list-change-packages List recent ChangePackage rows with gate decisions. limit (default 20) ci-agent list-change-packages 50
    export-signals-json Export candidate signals to a JSON file. --output/-o (default data/signals.json), --limit (200) ci-agent export-signals-json -o out.json
    export-signals Export candidate signals to a self-contained HTML report. --output/-o (default data/signals_report.html), --limit (200) ci-agent export-signals

    Note

    In server mode nothing consumes the queue automatically. schedule-once only enqueues; you must run worker-once (or dev-run-once, or a production Service Bus consumer) for jobs to execute. The first scan of any source produces a baseline only and emits no signals.

    Layer 2 — intelligence pipeline & inspection¶

    Command Purpose Key flags Example
    process-layer2 Run the Layer 2 pipeline over unprocessed candidate signals; prints a run-result counter summary. --scan-run-id, --candidate-signal-id, --limit (100) ci-agent process-layer2 --limit 50
    layer2-dev-run Dev convenience: run the pipeline, then print the resulting detected changes. --limit (100) ci-agent layer2-dev-run
    run-pipeline Convenience: optionally load-config, then run a full Layer 1 scan, then Layer 2. --config, --limit (100) ci-agent run-pipeline --config examples/config/godrej_competitors.yaml
    list-event-clusters List EventCluster rows (competitor, category, action, status). limit (default 50) ci-agent list-event-clusters
    list-detected-changes List DetectedChange rows (competitor, significance, category, title). limit (default 50) ci-agent list-detected-changes
    list-alert-candidates List AlertCandidate rows queued for dispatch. limit (default 50) ci-agent list-alert-candidates
    list-digest-entry-drafts List DigestEntryDraft rows prepared for the weekly digest. limit (default 50) ci-agent list-digest-entry-drafts
    export-report Generate an HTML intelligence report from detected changes (via scripts/export_html_report.py). --out (default data/intelligence_report.html) ci-agent export-report --out report.html

    Feedback¶

    Command Purpose Key flags Example
    feedback-submit Record analyst feedback on a change, cluster, or signal (does not apply side-effects). one of --change-id / --cluster-id / --signal-id; --verdict (required); --reason; --analyst (default analyst) ci-agent feedback-submit --change-id <id> --verdict false_positive
    feedback-list List analyst feedback entries. --unapplied, --limit (50) ci-agent feedback-list --unapplied
    feedback-apply Apply feedback side-effects (archive false positives, reset for reanalysis, create suppressions). --id or --all ci-agent feedback-apply --all
    feedback-suppressions List active Layer 1 FeedbackSuppressionEntry rules. --limit (100) ci-agent feedback-suppressions
    feedback-stats Show governance statistics (feedback, patterns, proposals, active rules/packs). — ci-agent feedback-stats
    compile-policies Compile active policy rules into a CompiledPolicyPack for an agent. AGENT_NAME (positional, required); PACK_NAME (positional, default default) ci-agent compile-policies impact_analysis

    Note

    feedback-submit and feedback-apply are two steps: submit records the verdict; apply executes the side-effects. Verdicts accepted by the CLI include correct, false_positive, low_priority, and needs_reanalysis. See Feedback & Learning Governance.

    Scoring weights¶

    Command Purpose Key flags Example
    scoring-weights-list List all ScoringWeightProfile entries. — ci-agent scoring-weights-list
    scoring-weights-create Create a profile seeded with current defaults. --name (default default), --activate/--no-activate (default activate) ci-agent scoring-weights-create --name tuned
    scoring-weights-show Print the currently active weights as a table. — ci-agent scoring-weights-show
    scoring-weights-activate Activate a profile by ID (deactivates any other active one). PROFILE_ID (positional, required) ci-agent scoring-weights-activate <id>
    scoring-weights-adjust Adjust one category weight by an integer delta (clamped 0–100). --profile-id, --key, --delta (all required); --reason ci-agent scoring-weights-adjust --profile-id <id> --key "Product Launch" --delta 5

    Agent configuration¶

    Command Purpose Key flags Example
    agent-config-list List all per-agent feedback configurations. — ci-agent agent-config-list
    agent-config-feedback Submit an instruction/correction/example/constraint to a pipeline agent. --agent, --type, --text (all required); --by (default admin) ci-agent agent-config-feedback --agent impact_analysis --type instruction --text "..."
    agent-config-show Show full config and feedback notes for one agent. --agent (required) ci-agent agent-config-show --agent impact_analysis
    agent-config-reset Clear the prompt addendum and feedback notes for an agent. --agent (required) ci-agent agent-config-reset --agent impact_analysis

    Query & delivery¶

    Command Purpose Key flags Example
    query-profile Natural-language Q&A over a competitor's profile and recent changes (LLM). --competitor/-c, --question/-q (required); --max-changes (10) ci-agent query-profile -c "HUL" -q "What is their pricing strategy?"
    digest-assemble Assemble the weekly digest from ready detected changes; persists a draft WeeklyDigest. --week (ISO label, e.g. 2026-W24; defaults to current) ci-agent digest-assemble
    digest-list List recent weekly digests. --limit (10) ci-agent digest-list
    digest-send Send a digest via email. --digest-id, --to (comma-separated, both required) ci-agent digest-send --digest-id <id> --to a@x.com,b@x.com
    digest-preview Print a digest's HTML (or plain-text) body to stdout. --digest-id (required); --plain ci-agent digest-preview --digest-id <id> --plain
    pipeline-health Print a summary of pipeline health and recent feedback. — ci-agent pipeline-health

    Note

    Email is skipped (status skipped) if SMTP_HOST is unset; Teams alerts are skipped if TEAMS_WEBHOOK_URL is unset. See Configuration & Environment.
