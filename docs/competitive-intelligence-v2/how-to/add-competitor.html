    Add a Competitor & Sources¶

    This guide walks you through registering a new competitor and its sources so the scanner can start collecting signals. You can do this in bulk from a YAML config file (best for initial setup) or one at a time through the API/admin panel (best for incremental changes). By the end you will have a Competitor row with one or more Source rows attached to it.

    Prerequisites¶

    • The database has been initialized (ci-agent init-db). See Installation & Setup.
    • You know which source types you need (website_page, website_scope, news_search, careers, blog, social).
    • For API/panel edits, the server is running (uvicorn app.main:app --reload).

    Option A — Edit YAML and load it¶

    This is the fastest way to add several competitors and their sources at once. The loader (app/admin/yaml_loader.py) reads a YAML file and creates one Competitor per entry plus a Source per sources: item.

    Step 1 — Add the competitor block¶

    Edit examples/config/godrej_competitors.yaml (or a copy) and append a competitor. Identity fields map to the competitor's *_json columns and are used later for relevance and disambiguation.

    competitors:
  - name: Marico Limited
    description: FMCG major, hair and edible oils
    market_positioning: Value + premium personal care
    tier: Tier1                      # Tier1 | Tier2 | Tier3
    aliases: [Marico, Marico Ltd]
    legal_names: [Marico Limited]
    known_domains: [marico.com]
    brand_names: [Parachute, Saffola, Livon]
    product_names: [hair oil, edible oil]
    leadership_names: [Saugata Gupta]
    industry_terms: [FMCG, personal care]
    negative_terms: [Marico County]  # disambiguation, filters false hits
    custom_keywords: [D2C, premiumisation]
    sources:
      - name: Marico website scope
        source_type: website_scope
        url: https://marico.com/
        frequency: weekly            # daily | weekly | manual
        config:                      # free-form; OVERRIDES matching .env keys
          seed_urls: [https://marico.com/newsroom]
          include_patterns: [/brands/, /news/]
          exclude_patterns: [/privacy, /cookie]
          max_pages_per_scan: 25
      - name: Marico news search
        source_type: news_search
        config: {provider: tavily, query_budget: 12, recency_window_days: 7}
      - name: Marico careers
        source_type: careers
        config: {ats_type: auto_detect}
      - name: Marico social
        source_type: social
        config: {linkedin_company_url: https://www.linkedin.com/company/marico, max_posts: 20}

    Note

    The per-source config: block overrides matching keys from .env. For example, setting provider: tavily on a news_search source wins over the global NEWS_PROVIDER setting.

    Step 2 — Load the config¶

    ci-agent load-config examples/config/godrej_competitors.yaml
# equivalent to: python -m app.cli load-config examples/config/godrej_competitors.yaml

    The loader prints {competitors_created, sources_created} counts.

    Warning

    load-config always inserts — it does no dedup or upsert. Re-running it on the same file creates duplicate competitors and sources. To add just one competitor to an existing DB, load a file that contains only the new competitor, or use Option B.

    Option B — Add via the API or panel¶

    Use this for incremental, one-off additions where a full config reload would create duplicates.

    Step 1 — Create the competitor¶

    POST /admin/competitors
{
  "name": "Marico Limited",
  "description": "FMCG major, hair and edible oils",
  "market_positioning": "Value + premium personal care",
  "tier": "Tier1",
  "aliases_json": ["Marico", "Marico Ltd"],
  "known_domains_json": ["marico.com"],
  "brand_names_json": ["Parachute", "Saffola"],
  "negative_terms_json": ["Marico County"],
  "is_active": true
}

    Returns 201 with the created competitor (including its id).

    Step 2 — Add sources¶

    Sources can be created nested under the competitor or flat (the flat form requires competitor_id).

    POST /admin/competitors/{competitor_id}/sources
{
  "source_type": "news_search",
  "name": "Marico news search",
  "config_json": {"provider": "tavily", "query_budget": 12, "recency_window_days": 7},
  "frequency": "weekly",
  "is_active": true
}

    POST /admin/sources
{
  "competitor_id": "<competitor_id>",
  "source_type": "careers",
  "name": "Marico careers",
  "config_json": {"ats_type": "auto_detect"},
  "frequency": "weekly",
  "is_active": true
}

    Both return 201. In the panel, the same forms live under Admin Control → Competitors and Admin Control → Sources.

    Choosing source types and config¶

    source_type Typical config keys
    website_page (single URL, no extra config)
    website_scope seed_urls, include_patterns, exclude_patterns, max_pages_per_scan
    news_search provider (bing/brave/tavily/auto), query_budget, recency_window_days, bing_market
    careers ats_type (auto_detect/greenhouse/lever/workday), greenhouse_token, lever_company, workday_url
    blog (RSS/HTML index URL)
    social linkedin_company_url, twitter_handle, max_posts, apify_token

    See Configure a News Profile for richer news relevance control beyond the basic news_search config.

    Avoid duplicates on reload¶

    Because load-config never deduplicates, adopt one of these habits:

    • Keep the master YAML authoritative and only run load-config against a fresh database (after init-db).
    • For live databases, add competitors via Option B (API/panel).
    • Soft-delete stray duplicates with DELETE /admin/competitors/{id} (deactivates, returns 204).

    Verify¶

    ci-agent status        # shows competitor / source counts

    Or check the panel: Admin Control → Competitors lists what was created, and drilling into a competitor shows its sources.
