    Configure a News Profile¶

    This guide shows you how to create and tune a competitor news profile — the rich configuration that drives query generation and relevance filtering for news_search sources. You will create a profile, preview the queries it generates, dry-run relevance against a sample article, and version/roll back changes safely. For how the news adapter and query planner use this profile, see Layer 1 — Source Scanning.

    Prerequisites¶

    • The competitor already exists (see Add a Competitor & Sources).
    • The server is running (uvicorn app.main:app --reload).
    • The competitor has (or will have) a news_search source.

    What a news profile controls¶

    A CompetitorNewsProfile supplies the query planner (build_queries_from_profile) and the relevance gate (profile_relevance_check) with:

    • Identity & disambiguation: display_name, short_name, parent_company, legal_names_json, aliases_json (each alias can require context terms), negative_terms_json, exclusion_rules_json.
    • Brands: brands_json (each brand can require company context / required terms / active flag).
    • Markets: primary_market, monitored_markets_json, excluded_markets_json, global_parent_policy.
    • Sources of truth: official_domains_json, newsroom_urls_json, investor_urls_json, careers_urls_json.
    • Tuning: industry_terms_json, strategic_keywords_json, leaders_json, query_config_json, relevance_config_json, source_trust_json.

    When an active profile exists, the news adapter picks it up via context["news_profile"] (or the DB) and uses build_queries_from_profile; otherwise it falls back to build_queries(competitor).

    Step 1 — Create the profile¶

    POST /admin/competitors/{competitor_id}/news-profile
{
  "display_name": "Hindustan Unilever",
  "short_name": "HUL",
  "parent_company": "Unilever",
  "tier": "Tier1",
  "aliases_json": [{"alias": "HUL", "requires_context": false}],
  "brands_json": [{"brand": "Dove", "requires_company_context": true, "active": true}],
  "primary_market": "India",
  "monitored_markets_json": ["India"],
  "official_domains_json": ["hul.co.in", "unilever.com"],
  "negative_terms_json": ["Hulu", "Hull City"],
  "query_config_json": {"query_budget": 12, "recency_window_days": 7},
  "relevance_config_json": {}
}

    Returns 201 and records version v1 plus an audit entry. A 409 means a profile already exists for that competitor — use PATCH instead. In the panel, use Admin Control → News Profiles.

    Step 2 — Preview generated queries¶

    Before scanning, check what the query planner will actually search for. This is a read-only dry run — no fetching happens.

    GET /admin/competitors/{competitor_id}/news-profile/preview-queries?budget=10

    {
  "source": "...",
  "profile_version": 1,
  "queries": ["Hindustan Unilever news", "HUL Dove launch", "..."],
  "count": 10
}

    If the queries look too broad or miss a brand, adjust aliases_json, brands_json, strategic_keywords_json, or query_config_json.query_budget and preview again.

    Step 3 — Test relevance¶

    Dry-run the relevance gate against a sample article to confirm it passes real news and suppresses noise. When an active profile exists this runs profile_relevance_check; otherwise it uses fast_relevance_check.

    POST /admin/competitors/{competitor_id}/news-profile/test-relevance
{
  "title": "HUL launches new Dove serum in India",
  "snippet": "Hindustan Unilever announced ...",
  "url": "https://economictimes.indiatimes.com/..."
}

    {
  "decision": "pass",          // pass | suppress | llm_review
  "reasons": ["alias match: HUL", "brand match: Dove", "market: India"]
}

    Tune negative_terms_json and exclusion_rules_json to turn false hits into suppress, and adjust required-context terms if legitimate articles come back as suppress.

    Step 4 — Update and version¶

    Every update snapshots the previous state into a CompetitorProfileVersion and writes an audit diff.

    PATCH /admin/competitors/{competitor_id}/news-profile
{
  "negative_terms_json": ["Hulu", "Hull City", "Unilever plc split"],
  "change_reason": "Filter parent-company restructuring noise"
}

    List versions to review history:

    GET /admin/competitors/{competitor_id}/news-profile/versions?limit=20

    Step 5 — Roll back if needed¶

    If a change made relevance worse, restore an earlier version. Rollback applies the chosen snapshot and records a new version marked is_rollback: true (it does not delete history).

    POST /admin/competitors/{competitor_id}/news-profile/rollback/{version_id}

    Re-run Step 2 and Step 3 after rolling back to confirm behavior is restored.
