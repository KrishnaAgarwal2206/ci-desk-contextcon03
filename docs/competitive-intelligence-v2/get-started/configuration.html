    Configuration & First Config Load¶

    In this tutorial you will understand the two configuration layers, set the minimum environment needed for a real LLM run, and load your first set of competitors and sources from a YAML file. When you finish, the database will contain the Godrej competitor set (HUL, P&G India, Marico, Dabur) and their sources, ready to scan.

    Prerequisites¶

    • You completed Installation & Setup — the app is installed, .env exists, and init-db has run.
    • Your virtual environment is active.

    1. The two configuration layers¶

    Configuration comes from two places, and it is important to know which wins:

    1. .env (global defaults) — read by pydantic-settings into a Settings singleton (get_settings()), resolved relative to the project root. This sets provider choices, keys, timeouts, and delivery options.
    2. Per-source YAML config blocks (local overrides) — each Source in the competitor YAML carries a free-form config: block stored as config_json. These override .env for that source (for example, a source can pin provider: tavily regardless of the global NEWS_PROVIDER).

    Note

    Rule of thumb: .env sets the defaults; a source's config: block overrides them for that source only.

    2. Minimum .env for a real-LLM run¶

    The tutorials run offline with the mock provider, so you can skip this step for now. When you are ready for a real run against Azure OpenAI and live news, set these keys — using placeholders here; put real values only in your local, gitignored .env:

    LLM_PROVIDER=azure_openai
AZURE_OPENAI_ENDPOINT=https://<your-resource>.openai.azure.com
AZURE_OPENAI_API_KEY=<AZURE_OPENAI_API_KEY>
AZURE_OPENAI_MODEL=gpt-4o
NEWS_PROVIDER=tavily
TAVILY_API_KEY=<TAVILY_API_KEY>

    Danger

    Never paste real secrets into documentation, commits, or the YAML files. Use placeholders like <AZURE_OPENAI_API_KEY> and https://<your-resource>.openai.azure.com. Real values belong only in your local .env, which is gitignored.

    For the full list of keys, see Configuration & Environment.

    3. The competitor YAML shape¶

    Competitors and their sources are defined in YAML under examples/config/. The shipped file examples/config/godrej_competitors.yaml defines Tier-1 competitors and their sources. A single competitor looks like this:

    competitors:
  - name: Hindustan Unilever Limited
    tier: Tier1
    aliases: [HUL]
    known_domains: [hul.co.in, unilever.com]
    brand_names: [Dove, Lux]
    negative_terms: [Hulu, Hull City]   # disambiguation
    custom_keywords: [premiumisation, D2C]
    sources:
      - name: HUL website scope
        source_type: website_scope       # website_page | website_scope | news_search | careers | blog | social
        url: https://www.hul.co.in/
        frequency: weekly                 # daily | weekly | manual
        config:                           # free-form; OVERRIDES .env for this source
          seed_urls: [https://www.hul.co.in/brands/]
          include_patterns: [/brands/, /news/]
          exclude_patterns: [/privacy, /cookie]
          max_pages_per_scan: 25
      - name: HUL news search
        source_type: news_search
        config: {provider: tavily, query_budget: 12, recency_window_days: 7}

    Top-level fields like aliases, known_domains, and brand_names are stored on the Competitor as *_json columns; each source's config: block is stored as Source.config_json.

    Tip

    A smaller examples/config/sample_competitors.yaml exists as a lightweight test variant if you want to start with fewer sources.

    4. Load the config¶

    Load the competitors and sources into the database:

    ci-agent load-config examples/config/godrej_competitors.yaml
# equivalent: python -m app.cli load-config examples/config/godrej_competitors.yaml

    The command reports how many competitors and sources it created.

    Warning

    load-config always inserts — it has no upsert or dedup logic. Running it a second time on the same file creates duplicate competitors and sources. Load each file once, or clean up duplicates afterward. See Add a Competitor & Sources.

    5. Verify¶

    Confirm the data landed, either from the panel or the CLI:

    ci-agent status

    Open http://localhost:8000/admin/panel and check the Admin Control screens — you should see the competitors and their sources listed. See Admin Control Plane.
