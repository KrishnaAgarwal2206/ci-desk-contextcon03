    LLM Abstraction¶

    Every LLM call in the system goes through a single one-method interface, returns structured JSON, and never crashes the caller. This page explains that interface, how a provider is selected, the difference between the Azure and mock providers, the full prompt catalog across all three subsystems, and how traces and cost are recorded.

    The one-method interface¶

    The contract is app/llm/contracts.py, a Protocol with exactly one method:

    complete_json(prompt_name, prompt_version, system_prompt, user_payload: dict, response_schema: dict) -> LLMResult

    There is no separate complete or chat — everything is structured JSON. The LLMResult (app/schemas/llm.py) carries output_json, provider, model, token_usage, latency_ms, raw_text, and error_message. A companion LLMTraceDraft is persisted to the llm_traces table for every call.

    LLM failures never crash the pipeline

    On any error — content filter, length truncation, non-JSON output, or a transport failure — the provider returns an LLMResult with error_message set and output_json empty ({}). Callers check the result; they never catch an exception from the provider. This is why every LLM-using step has a deterministic fallback path.

    Provider selection¶

    app/infra.py build_llm_provider() returns an AzureOpenAIProvider when LLM_PROVIDER == azure_openai, otherwise a MockLLMProvider. The CLI has its own _build_llm_provider() that additionally wires a DB session factory so cost-ledger rows can be written from CLI runs.

    AzureOpenAIProvider¶

    app/llm/azure_openai_provider.py lazily constructs openai.AzureOpenAI(azure_endpoint, api_key, api_version="2024-08-01-preview"). The model is AZURE_OPENAI_MODEL (the deployment name, default gpt-4o). It requests response_format={"type": "json_object"} and sets max_completion_tokens to 4096 for the heavy prompts (impact_analysis, competitor_query, maintenance_copilot, final_classifier) and 1024 otherwise. It never raises: content-filter and length-truncation cases become error_message, non-JSON output is wrapped as {"raw_text": ...}. Each call writes an LLMCostLedger row via _write_cost_ledger().

    MockLLMProvider¶

    app/llm/mock_provider.py (PROVIDER="mock", MODEL="mock-v1") is deterministic and does no network I/O. Its _route() dispatches on prompt_name substrings to a canned response for every prompt in the catalog, with fixed token_usage of {prompt: 100, completion: 50, total: 150}. This is what powers the offline test suite (tests run with no keys).

    The prompt catalog¶

    Every prompt used anywhere in the system, grouped by subsystem. All go through complete_json and are recorded as LLMTrace rows.

    Layer 1 — analysis (max_completion_tokens 1024)¶

    Prompt Version Analyzer Purpose
    website_semantic_diff v1 Website meaningful positioning shift vs noise
    careers_role_normalizer v1 Careers classify job title → function
    careers_pattern_interpreter v1 Careers hiring surge / geo expansion → signal
    news_relevance_resolver v1 News is a borderline article about this competitor
    news_event_extractor v1 News extract business event + signal_type
    blog_social_post_interpreter v1 BlogSocial interpret a post → signal

    Layer 2 — intelligence pipeline¶

    Prompt Version Step Purpose
    signal_normalizer v1 Normalization (4) subject-action-object, normalize entities, claim status
    event_merge_judge v1 Clustering (8) same real-world event? (conservative)
    final_classifier v1 Classification (9) one of 10 categories
    impact_analysis v2 Impact (11) grounded GCP business impact (headline, so_what, threat level)
    profile_narrative v1 Profile narrative (14) 3–4 sentence executive narrative
    competitor_query v2 out-of-pipeline NL Q&A over profiles + changes

    Feedback governance & ops¶

    Prompt Version Where Purpose
    weight_adjustment v1 legacy feedback scoring-weight deltas from a verdict
    policy_consolidation v1 POST /admin/policy-health/{id}/consolidate merge / retire / convert policy rules
    maintenance_copilot v1 POST /admin/observability/copilot ops assistant + action suggestions
    nl_command v1 POST /admin/feedback/nl-command parse free-text into a governance action

    The governance core is deterministic

    Feature extraction, pattern mining, and proposal generation use no LLM. The only LLM touch-points in the feedback subsystem are the legacy weight_adjustment call, policy_consolidation, and eval runs that exercise LLM agents. See Feedback & Learning Governance.

    The impact_analysis v2 system prompt hardcodes GCP identity, brand/category/market lists, 15 grounding rules, and an exact output-key contract.

    Traces and cost¶

    Every call produces an LLMTrace (provider, model, prompt name/version, input hash, output, token usage, latency, error). The AzureOpenAIProvider additionally writes an LLMCostLedger row, priced from the active LLMPriceCatalog (seeded at startup: input $0.005/1k, output $0.015/1k, cached $0.0025/1k; fallback 0.005/0.015). Costs then roll up through the telemetry hierarchy. See Observability & Telemetry.
